## [2.0.0] — 2026-11-05

### Added

- Кнопка «Сказать» на странице колонки: введённый текст (до 500 символов)
  синтезируется локальным Piper-сервисом `tts` из того же compose и
  проигрывается на колонке через `aplay`. Сервис работает только во
  внутренней сети и наружу не публикуется.
- Локальная веб-панель `webui` на Flask: список колонок, статус Bridge,
  установка/обновление, routing, запись ключа. Панель запускается в
  Docker; на хосте не требуется Python/Flask/ssh/adb.
- Очередь заданий с последовательным выполнением на одну колонку,
  журналом и автообновлением страницы задания.
- Управление `secrets/router-routes.json`: просмотр, редактирование,
  удаление, health и перезапуск роутера. Запись атомарная, конфиг
  проверяется штатным `load_config()`.
- Политика маршрутизации: «день недели» больше не уходит в Яндекс безусловно; добавлено правило `yandex_weekday` только для «сегодня/сейчас/вчера/завтра», а контекстные вопросы о дне недели и дате рождения идут в LLM (FLAI).
- Первый TTS-кусок ответа ограничен ~40 символами (`QUASAR_SPEECH_FIRST_CHARS`): станция синтезирует запрос целиком, поэтому короткое начало начинает звучать заметно раньше.
- LLM-роутер пересылает SSE-события сразу по мере поступления: `read1()`
  вместо `read(8192)`, который на chunked-ответе ждал 8 КБ или конца
  потока и задерживал первый токен.
- Upstream-ключи стали общим списком: ключ добавляется в разделе
  «Ключи» (файл и значение), а маршруты выбирают его из
  списка. Используемый ключ нельзя удалить; старые `api_key_file`
  импортируются автоматически.
- Смена промежуточного токена сразу записывает его в колонку по
  `LLM_TOKEN_FILE` профиля и запускает задачу «Записать ключ»; на странице
  остаётся ссылка на лог задачи.
- В образ `webui` добавляется passwd-запись для runtime-uid (иначе `ssh`
  в контейнере падает с `No user exists for uid`), а действиям с колонками
  выставляется `SPEAKER_TRUST_IP=1`: в контейнере ARP не видит LAN, поэтому
  используется `SPEAKER_IP` из профиля (доступ защищён SSH-ключом).
- Инвентарь ключей и ротация промежуточных токенов; страница «Ключи»
  разделена на промежуточные токены и upstream-ключи по фактическим файлам
  из `api_key_file`; без захардкоженных FLAI/Orca и размера в байтах.
- Вход по паролю (scrypt), сессии, CSRF и ограничение попыток.
- Аудит действий в `webui-state/audit.jsonl` с редактированием секретов.
- Шифрованные резервные копии настроек: вся конфигурация или одна
  колонка; AES-GCM + PBKDF2, скачивание и восстановление через панель,
  снапшот текущего состояния перед восстановлением.
- Полные MAC/device ID, модель производителя и цветная иконка колонки;
  цвет выбирается вручную и хранится в `webui-state/speaker-appearance.json`.
- Смена пароля из панели, обновлённый интерфейс с закладками разделов,
  центрированное окно входа.
- Управление маршрутами роутера: создание маршрута, отдельные строки для
  основного и запасных upstream, добавление/редактирование/удаление
  fallback, до 9 запасных, смена порядка стрелками ▲/▼ вместе с основным (на краях лишние стрелки скрыты); поддержка цепочки
  `fallbacks` в роутере.
- Название проекта в интерфейсе и заголовках — «Моя Яндекс Станция».
- Вкладка «Прошивка»: скачивание образа, список файлов прошивки,
  чек-лист сброса/привязки и действия по колонкам (поиск, SSH/OTA,
  Bridge, routing, ключи, проверка).
- `stand-control`: запуск, остановка и статус `lite-kit` из панели через
  узкий sidecar с Docker socket.
- Маршрутизация сообщений между колонками: `yandex_intercom` возвращает в Яндекс «передай…», «скажи всем…», объявления, трансляции и звонки.
- Расширены правила Яндекс-сервисов: громкость, треки, Bluetooth, микрофон, мультирум, новости, подкасты, календарь, списки, перевод, калькулятор, курсы, такси, рецепты, сценарии, состояния устройств без глагола и умный дом.
- Проверка доступности upstream: `GET /health?probe=1` дергает
  `GET /models` у основного и запасных маршрутов; статусы `ok`,
  `ошибка`, `недоступен`, `нет ключа` в панели.
- README и `docs/07-webui.md`: быстрый старт, вход, пароль, прошивка,
  стенд, маршруты, ключи, бэкапы, проверка доступности и риски.
- Узкий sidecar `router-control` с доступом к Docker только для
  перезапуска `llm-router`; панель не получает Docker API.
- `docker/Dockerfile.webui`, `docker/Dockerfile.webui-control`,
  `docker/Dockerfile.stand-control`, `docker/docker-compose.webui.yml`,
  `make webui*`.
- `docs/07-webui.md`, `deploy/webui.service`, `make webui` и
  `make webui-test`.

### Changed

- Иконки колонок перерисованы под реальную «Яндекс Станцию Лайт»
  первого поколения: короткий цилиндр, кольцо микрофонов, треугольный
  светодиод, тёмное основание с прорезями. Палитра шести цветов
  приближена к оригиналу — мята стала бирюзовой, фламинго и
  ультрафиолет насыщеннее.

## [Unreleased] — 2026-11-05

### Added

- Локальный LLM-роутер `llm-router` на `192.168.1.2:5002`:
  OpenAI-совместимые `/v1/chat/completions` и `/v1/models`, выбор
  upstream по промежуточному ключу колонки, hot reload конфига.
- Резервные (fallback) маршруты для каждого промежуточного ключа; при
  недоступности основного upstream запрос пересобирается под режим
  резервного (`history=client|server`).
- Режимы истории: `server` (FLAI хранит историю, роутер отправляет только
  текущий вопрос) и `client` (обычная LLM получает окно Bridge).
- Сессии FLAI: одна на колонку, ротация после 30 минут простоя,
  автоматическая чистка — остаются текущая и две предыдущие.
- `scripts/router-init.sh`, `scripts/start-router.sh`,
  `scripts/stop-router.sh`, `config/router-routes.example.json`,
  `docker/docker-compose.router.yml`, `make router*`.
- Профили колонок и `.env` переведены на адрес роутера и промежуточные
  ключи `secrets/router-token-*`.
- `scripts/set-speaker-key.sh` теперь записывает в Bridge адрес роутера,
  модель и промежуточный ключ.
- `history=server` больше не отправляет system-промпт: FLAI склеивает роли
  и мог цитировать служебные инструкции в ответе. Health-check вынесен в
  отдельную сессию `voice-health` и не засоряет основной диалог.
- Роутер обрезает не-stream ответы любой LLM до 3 предложений / 400
  символов и убирает Markdown (`response` в конфиге).
- Кастомный Bridge `0.6.2-chunked`: длинный ответ режется на TTS-куски
  по ~500 символов (до 6 кусков) и озвучивается непрерывно. Новый Bridge
  присылает `X-Quasar-Voice-Chunking: 1`; роутер для таких запросов отдаёт
  до 3000 символов (`response.chunked`), старые Bridge — 3/400.
- `scripts/build-quasar-bridge.sh` собирает arm64-релиз в Docker;
  `install-quasar-bridge.sh` автоматически выбирает `v0.6.2-chunked`.
  Раскатано на все четыре колонки: `192.168.1.101`, `192.168.1.100`, `192.168.1.102`, `192.168.1.103`.
- Streaming LLM → TTS в Bridge: SSE-клиент, буфер предложений, очистка
  Markdown, динамическая очередь TTS, keepalive для медленного поиска и
  idle-таймаут 90 секунд. Пилот включён на `192.168.1.101` и `192.168.1.100` через
  `QUASAR_STREAM_LLM=1`.
- Фразы-заполнители при задержке первого текста: первая через 10 секунд,
  затем каждые 15 секунд, максимум 3; список настраивается через
  `QUASAR_SPEECH_FILLERS`. При первом дельте реального текста очередь
  заполнителей очищается, чтобы ответ не ждал их.
- Убрано вырезание служебных фраз: приглашения вида «спроси нейросеть»
  больше нет в коде и документации; обычный вопрос уходит в LLM по
  `default_route=llm`.
- Тесты роутера: `router/tests/test_router.py` (14 тестов).
- FLAI назначен `primary` для всех четырёх маршрутов; upstream-ключи
  разложены по учётным записям `speaker-a`, `speaker-b`, `speaker-c`, `speaker-d`.
- Для всех четырёх маршрутов настроен fallback OrcaRouter Free
  (`https://api.orcarouter.ai/v1`, модель `orcarouter/free`, ключи
  `secrets/orca-token-*`). Ключи валидны, но free-тариф может отдавать
  `429 free_rate_limited`.

### Changed

- `check-flai.sh` проверяет LLM через роутер, а не напрямую FLAI.
- `README.md` и `docs/03-runbook.md` описывают роутер, fallback и
  управление сессиями.
- В runbook и troubleshooting добавлено: перед Bluetooth-сопряжением каждой
  следующей колонки полностью закрывать и заново открывать «Дом с Алисой».

## [1.0.0] — 2026-11-04

Первая версия: подготовка инфраструктуры и документации.

### Added

- README с описанием проекта, ограничениями и быстрым стартом.
- `docs/01-findings.md`: результаты разведки колонки, FLAI и сети.
- `docs/02-plan.md`: этапы, критерии успеха, журнал решений.
- `docs/03-runbook.md`: пошаговые команды root, SSH, OTA, Bridge.
- `docs/04-risks.md`: риски, ограничения, откат.
- `docs/05-troubleshooting.md`: диагностика типовых ошибок.
- Скрипты `check-flai`, `resolve-speaker`, `fetch-firmware`,
  `start-lite-kit`, `stop-lite-kit`, `post-root-ssh`,
  `install-quasar-bridge`.
- `resolve-speaker.sh` ищет колонку по `device_id`/MAC, IP — только
  подсказка. Все установочные скрипты используют его вместо хардкода IP.
- `fetch-quasar-bridge.sh` скачивает проверенный релиз v0.6.2 в локальный
  кэш; установка больше не зависит от доступности GitHub release-assets.
- `bridge_install_pexpect.py` проводит официальный мастер через PTY:
  обычный pipe с `ssh -tt` закрывался раньше, чем `setup.sh` читал ответы.
- `install-quasar-bridge.sh --non-interactive` теперь использует этот
  драйвер и локальный релиз.
- Политика `config/quasar-bridge-policy.json`: `default_route = llm`;
  Яндекс обрабатывает только погоду, время, музыку, таймеры и умный дом.
- Переменные `LLM_*` (endpoint, upstream, модель, ключ) с алиасами
  `FLAI_*`: вместо FLAI подойдёт любая OpenAI-совместимая LLM.
- Профили `config/speakers/example.env` и `scripts/lib-env.sh`: все команды
  принимают `SPEAKER_ENV=...` и находят колонку по MAC/device ID.
  Без профиля используется `local/.env` (или `.env` в корне).
- Персональные ключи FLAI по колонкам: `secrets/flai-token-speaker-a`,
  `-speaker-b`, `-speaker-c`, `-speaker-d`; профили содержат
  `LLM_TOKEN_FILE`.
- `scripts/set-speaker-key.sh` записывает ключ в
  `/data/opt/quasar-bridge/runtime.env` на колонке и перезапускает Bridge.
- `make status` больше не вызывает LLM; health-probe «Ответь одним словом:
  связь» вынесен в `make check-backends`, чтобы не засорять историю FLAI.
- `conversation_log` включает журнал распознанных фраз и ответов для
  диагностики маршрутизации.
- Подтверждён целевой сценарий с камерой: FLAI делает
  `camera_snapshot(room=kab)`, Qwen3VL описывает снимок, Bridge передаёт
  текст в Yandex TTS, Алиса озвучивает.
- Bridge подключается к внешней LLM напрямую; прокси и вырезание
  служебных обращений удалены. Служебное обращение больше не обрабатывается.
- Внешняя LLM получает распознанный текст без слова «Алиса»; остальной
  текст передаётся как есть.
- Docker-стенд `lite-kit` с host-network: DNS 53, HTTP 80, HTTPS 443.
- Снапшоты `quasar-bridge` v0.6.2, `lite-kit` и station-tools.
- Конфигурационные примеры для FLAI и колонки.
