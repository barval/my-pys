# Открытие релизной ветки my-pys

## Обзор

Открытие линии — **механический** шаг. Оно режет ветку и переименовывает
версию, которую печатает продукт. Оно не решает, что войдёт в релиз.

Каждая строка в таблице маркеров обязательна: это ровно те места, где
версия видна пользователю, API, тестам или агенту. Всё остальное, где
встречается старая версия, — **историческая справка**; её не переписывают
вслепую, а перечисляют в отчёте.

## Входы

Спросите два значения, остальное выведите и озвучьте до любых правок.

| Вход | Пример | Производное |
|---|---|---|
| `SOURCE` — релизная ветка, от которой режем | `v2.1` | `PREV=2.1` |
| `TARGET` — новая линия | `v2.2` | `2.2`, тег `2.2` |

Откажитесь работать, если: рабочее дерево грязное, `TARGET` уже есть
локально или на `origin`, `TARGET` не новее `SOURCE`, `SOURCE` не
существует, версия не в формате `X.Y` (без третьего компонента).

## Жёсткие правила

- Сначала покажите план: файл, строка, было, стало. Без явного «да» не
  создавайте ветку, не правьте файлы, не коммитьте, не пушьте и не
  ставьте тег.
- **Никаких `sed -i 's/2.1/2.2/'`.** Рядом живут `2.1rem` в CSS,
  `192.168.1.x`, исторические разделы `CHANGELOG.md` и комментарий ключа
  `ysl-v2.1`. Правьте только строки из таблицы.
- Открытие — первое действие цикла. Фича-ветки режутся **от `TARGET`**
  уже после открытия; ветка от `SOURCE` относится к прошлой линии и
  молча не попадёт в новую.
- `master` не трогать: только `vX.Y`, слияние в `master` — отдельное
  решение владельца.
- Секреты, реальные IP, MAC, device ID, имена колонок и комнат в правки
  не попадают. Примеры — только синтетические.
- Коммит — по команде. Сообщение в стиле проекта:
  `chore: open vX.Y release line`.

## Фаза 0 — Проверка (только чтение)

```bash
git fetch --all --prune
git status --short                      # должно быть пусто
git branch --show-current
git branch --list "v2.2"                # должно быть пусто
git ls-remote --heads origin "v2.2"
git log -1 --format='%h %ad %s' --date=short "v2.1"
```

Если дерево грязное — остановитесь. Чужие файлы (например,
`graphify-out/`, `.cache/`) не удалять и в коммит не добавлять.

## Фаза 1 — Ветка

```bash
git checkout -b "v2.2" "v2.1"
```

Только от релизной ветки. Если `v2.2` уже есть на `origin` — линия уже
открыта, остановитесь.

## Фаза 2 — Маркеры версии

| Что | Файл | Как должно выглядеть |
|---|---|---|
| Файл версии | `VERSION` | `v2.2` |
| Константа пакета | `webui/__init__.py` | `__version__ = "2.2"` |
| User-Agent роутера | `router/llm_router.py` | `"User-Agent": "llm-router/2.2"` — **две** строки (`probe_upstream`, `_forward`) |
| Версия TTS-сервиса | `scripts/tts_server.py` | `server_version = "my-pys-tts/2.2"` |
| README | `README.md` | `**Версия:** v2.2` |
| Правила агента | `AGENTS.md` | раздел «2. Версия»: текущая версия, `VERSION`, `__version__`, тег, «в интерфейсе и `/healthz`» |
| Ветки | `CONTRIBUTING.md` | `v2.2` — текущая рабочая ветка; новые ветки от `v2.2` |
| Индекс документации | `docs/README.md` | «Актуальное состояние v2.2» |
| Ограничения | `docs/04-risks.md` | `## Ограничения v2.2` |
| Шаг релиза | `docs/03-runbook.md` | тег `v2.2` в шаге «Закоммитить и поставить тег» |
| Тесты панели | `webui/tests/test_app.py` | `payload["version"] == "2.2"` и шапка `<small>v2.2</small>` |
| История | `CHANGELOG.md` | `## [2.2] — Unreleased` сверху, раздел `2.1` с датой |

Версия в интерфейсе и `/healthz` берётся из `webui/__init__.py` — шаблоны
не правятся.

## Фаза 3 — CHANGELOG

1. Верхний раздел `## [Unreleased]` переименовать в `## [2.2] — Unreleased`.
2. Убедиться, что предыдущий раздел датирован (`## [2.1] — 2026-11-06`).
3. Новый раздел оставить без подразделов, пока в нём нет содержимого:
   пустые `### Добавлено` не добавлять.

Раздел живёт как `Unreleased` весь цикл; дату ставит подготовка релиза.
Правки, сделанные за цикл, дописываются в него по мере работы.

## Фаза 4 — Проверка

```bash
python3 .opencode/skills/opening-my-pys-release/scripts/check_version_markers.py \
  --version 2.2 --previous 2.1
ruff check webui router scripts
python3 -m compileall -q webui router scripts
bash -n scripts/*.sh
```

Скрипт возвращает `0`, когда обязательные маркеры верны, и печатает
оставшиеся вхождения старой версии как `REVIEW`. Каждую строку прочитать:
история, CSS (`2.1rem`), IP-адреса и комментарий ключа — ожидаемы;
`REVIEW` в файле, который печатает текущую версию, — пропущенный маркер.

Тесты — узкие и только с разрешения пользователя (см. `AGENTS.md`, раздел 6):
`python3 -m pytest webui/tests/test_app.py -q`. Перед запуском проверить
`pgrep -c pytest` и `free -h`.

## Фаза 5 — Отчёт

```text
Релизная линия v2.2 — ОТКРЫТА / ЗАБЛОКИРОВАНА

Ветка:        v2.2 от v2.1 (<sha>, <дата>)
Версия:       2.2
Маркеры:      N/N верны
CHANGELOG:    2.1 датирован, 2.2 Unreleased
Проверки:     ruff / compileall / bash -n — PASS или NOT VERIFIED
REVIEW:       <сколько и как классифицированы>
Не проверено: <что и почему>
```

## Не трогать

| Похоже на версию | Что это на самом деле |
|---|---|
| `2.1rem` в `webui/static/app.css` | размер CSS |
| Рабочие адреса в примерах | синтетические адреса из документации |
| `ysl-v2.1` в `scripts/post-root-ssh.sh` | комментарий SSH-ключа, не версия продукта |
| `## [2.1]` и ниже в `CHANGELOG.md` | история релизов |
| `local/archive/**`, `graphify-out/**`, `.cache/**`, `backups/**` | вне git или runtime |
| `vendor/lite-kit/**`, `vendor/quasar-bridge/**` | сторонний код, версия не наша |

## Красные флаги

| Мысль | Реальность |
|---|---|
| «Один `sed` быстрее таблицы» | Он перепишет `2.1rem`, `192.168.1.x` и историю CHANGELOG. |
| «Сначала фича, версию потом» | Фича-ветка от `SOURCE` не попадёт в новую линию. |
| «Раздел `Unreleased` уже есть, трогать не надо» | Линия без своего раздела в CHANGELOG не открыта. |
| «Поставлю дату сразу» | До подготовки релиза раздел остаётся `Unreleased`. |
| «Каждое оставшееся `2.1` — ошибка» | Большинство — история, CSS и примеры. Классифицируйте. |
| «Обновлю `ysl-v2.1` заодно» | Это комментарий ключа; отдельным решением, не в открытии. |
