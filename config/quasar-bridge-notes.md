# Внешняя LLM для Quasar Bridge

Bridge отдаёт все не-сервисные запросы на локальный LLM-роутер
(`http://<хост>:5002/v1`), а роутер по промежуточному ключу колонки
выбирает upstream: FLAI, Ollama, vLLM, LM Studio, облачный
OpenAI-совместимый сервис и т.п. Списком upstream и ключей удобнее
управлять в веб-панели (`docs/07-webui.md`).

## Переменные

```bash
cp config/llm.env.example local/.env
```

| Переменная | Значение по умолчанию | Что значит |
|---|---|---|
| `LLM_BASE_URL` | `http://192.168.1.2:5002/v1` | адрес локального LLM-роутера |
| `LLM_MODEL` | `your-model` | имя модели; роутер подменяет его моделью upstream |
| `LLM_TOKEN_FILE` | `secrets/router-token-example` | промежуточный токен колонки (`sk-router-*`) |

`FLAI_*` оставлены как алиасы для совместимости. Эти переменные пишутся
не вручную, а `./scripts/set-speaker-key.sh` (или кнопкой «Записать ключ»
в панели) в `runtime.env` колонки; после этого Bridge перезапускается.
Upstream-провайдеры и их ключи задаются не здесь, а в маршрутах роутера
(`secrets/router-routes.json`).

## Маршрутизация

Политика лежит в `config/quasar-bridge-policy.json`:

- **Яндекс** обрабатывает только:
  - погоду;
  - время, дату, таймеры, будильники, напоминания;
  - музыку, радио, песни, треки, альбомы, плейлисты, исполнителей;
  - управление умным домом (свет, розетки, шторы, климат и т.п.);
  - паузу/продолжение/стоп текущего воспроизведения.
- **Внешняя LLM** обрабатывает всё остальное: вопросы, рассуждения,
  камеру, чтение страниц, историю и т.п.
- `default_route = llm`, поэтому классификатор не вызывается.

Применить:

```bash
./scripts/apply-bridge-routing.sh
```

Проверить маршрут без выполнения:

```bash
set -a; . /data/opt/quasar-bridge/runtime.env; set +a
pkg=/data/opt/quasar-bridge/app
"$pkg/bin/quasar-bridge" -config /data/opt/quasar-bridge/config.json -route "какая погода завтра"
```

| Фраза | Маршрут |
|---|---|
| «какая погода завтра» | `yandex` / `yandex_services` |
| «который час» | `yandex` / `yandex_services` |
| «включи музыку» | `yandex` / `yandex_services` |
| «найди песню Pink Floyd» | `yandex` / `yandex_services` |
| «включи свет в комнате A» | `yandex` / `home_devices` (пока нет Home Assistant) |
| «выключи музыку» | `yandex` / `speaker_playback` |
| «передай в кабинет…» | `yandex` / `yandex_intercom` |
| «скажи всем…» | `yandex` / `yandex_intercom` |
| «включи трансляцию» | `yandex` / `yandex_intercom` |
| «позвони…» | `yandex` / `yandex_intercom` |
| «громче» / «следующий трек» | `yandex` / `speaker_controls` |
| «новости» / «переведи…» | `yandex` / `yandex_services` |
| «запусти пылесос» | `yandex` / `home_devices` |
| «включи сценарий…» | `yandex` / `yandex_scenarios` |
| «подсветка кровати 10%» | `yandex` / `home_state` |

| «почему небо голубое» | `llm` / `default` |
| «как дела в комнате A» | `llm` / `default` |

## Что именно получает внешняя LLM

1. **Слово «Алиса» не передаётся.** Его съедает spotter колонки; в Bridge
   приходит уже распознанный текст без wake word.
2. Bridge отправляет на роутер системный промпт голосового помощника и
   распознанный текст как `user`-сообщение. Что именно уйдёт upstream,
   решает режим `history` маршрута в `secrets/router-routes.json`:
   `server` — только последний вопрос и стабильный `user`, `client` —
   окно Bridge. Для некоторых провайдеров (например, FLAI) system-промпт
   не отправляется, чтобы он не пересказывался в ответе.
3. Текст передаётся **как распознала Яндекс STT**, без дополнительной
   нормализации и без вырезания служебных обращений. Специальные фразы
   для вызова LLM не нужны: всё, кроме Яндекс-сервисов, идёт в LLM.
4. Если сработало правило Яндекса (погода, время, музыка, умный дом),
   внешняя LLM этот запрос не получает вообще.

## Камера (пример FLAI)

Если внешняя LLM — [FLAI](https://github.com/barval/flai) с доступом к камере, запрос

```
«Алиса, как дела в комнате A?»
```

уходит в LLM как «как дела в комнате A». FLAI вызывает
`camera_snapshot(room=kab)`, получает снимок, описывает его текстом, а
Bridge отдаёт текст в Yandex TTS — Алиса озвучивает.

## Ограничения FLAI

1. `response_format` игнорируется; классификатор Bridge не используется.
2. `temperature`, `max_tokens`, `chat_template_kwargs` игнорируются.
3. `tools`, `tool_choice`, `functions` игнорируются. Инструменты Bridge
   (`assistant_tools`) лучше держать выключенными.
4. Сложный запрос может идти 30–50 с. Таймаут Bridge — 60 с.
5. FLAI хранит сессии; голосовые запросы видны в веб-чате.

## Отдельный пользователь FLAI (по желанию)

1. В FLAI: «Администрирование» → «Пользователи» → создать `alice` (или отдельного пользователя у своего провайдера).
2. Войти как `alice`, создать API-ключ.
3. Заменить файл из `api_key_file` маршрута (например, `secrets/flai-token-speaker-a`).
4. Перезапустить Bridge.
