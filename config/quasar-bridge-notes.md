# Внешняя LLM для Quasar Bridge

Bridge умеет отдавать сложные запросы любой модели с OpenAI-совместимым
API. По умолчанию используется локальный FLAI, но его можно заменить на
Ollama, vLLM, LM Studio, облачный OpenAI-совместимый сервис и т.п.

## Переменные

Скопируйте пример и поправьте значения:

```bash
cp config/flai.env.example .env
```

| Переменная | Значение по умолчанию | Что значит |
|---|---|---|
| `LLM_BASE_URL` | `http://192.168.1.2:5001/v1` | endpoint, который видит Bridge (через прокси) |
| `LLM_UPSTREAM_URL` | `http://127.0.0.1:5000/v1` | настоящий endpoint LLM за прокси |
| `LLM_MODEL` | `flai-chat` | имя модели у провайдера |
| `LLM_TOKEN_FILE` | `secrets/flai-token` | файл с Bearer-ключом |

Старые имена `FLAI_*` поддерживаются как алиасы. Для другой LLM достаточно
поменять `LLM_UPSTREAM_URL`, `LLM_MODEL` и ключ, затем перезапустить прокси
и Bridge.

## Маршрутизация

Политика лежит в `config/quasar-bridge-policy.json`:

- **Яндекс** обрабатывает только:
  - погоду;
  - время, дату, таймеры, будильники, напоминания;
  - музыку, радио, песни, треки, альбомы, плейлисты, исполнителей;
  - управление умным домом (свет, розетки, шторы, климат и т.п.);
  - паузу/продолжение/стоп текущего воспроизведения.
- **Внешняя LLM** обрабатывает всё остальное: вопросы, рассуждения,
  камеру, чтение страниц, историю, явные обращения «спроси ФЛАЙ» и т.п.
- `default_route` = `llm`, поэтому классификатор не вызывается: решение
  принимается по правилам, а всё непопавшее уходит в LLM.

Применить политику:

```bash
./scripts/apply-bridge-routing.sh
```

Проверить решение без выполнения запроса (на колонке):

```bash
set -a; . /data/opt/quasar-bridge/runtime.env; set +a
pkg=/data/opt/quasar-bridge/app
"$pkg/bin/quasar-bridge" -config /data/opt/quasar-bridge/config.json -route "какая погода завтра"
```

Ожидаемые маршруты:

| Фраза | Маршрут |
|---|---|
| «какая погода завтра» | `yandex` / `yandex_services` |
| «который час» | `yandex` / `yandex_services` |
| «включи музыку» | `yandex` / `yandex_services` |
| «найди песню Pink Floyd» | `yandex` / `yandex_services` |
| «включи свет в комнате A» | `yandex` / `home_devices` (пока нет Home Assistant) |
| «выключи музыку» | `yandex` / `speaker_playback` |
| «почему небо голубое» | `llm` / `default` |
| «как дела в комнате A» | `llm` / `default` |
| «спроси у ФЛАЙ: …» | `llm` / `explicit_llm_phrase` |

## Нормализация служебного обращения

Bridge отправляет распознанный текст целиком. Чтобы внешняя LLM не видела
«Спроси у ФЛАЙ: …», между ними стоит прокси:

```text
колонка → Bridge → http://192.168.1.2:5001/v1
                         │  вырезает «спроси у ФЛАЙ», «спроси нейросеть» и т.п.
                         ▼
                    LLM http://127.0.0.1:5000/v1
```

Запуск:

```bash
./scripts/start-flai-proxy.sh
```

На колонке в `/data/opt/quasar-bridge/runtime.env`:

```sh
QUASAR_LLM_BASE_URL="http://192.168.1.2:5001/v1"
```

Прокси не требует ключа: он прозрачно передаёт `Authorization` в LLM.
Порт 5001 — только для локальной сети.

## Явные фразы

Правило `explicit_llm_phrase` стоит первым и отправляет в LLM запросы,
содержащие:

- `спроси у нейросети`
- `спроси у своей модели`
- `спроси у нейронки`
- `спроси нейросеть`
- `спроси свою модель`
- `спроси флай`
- `спроси у флай`

Фразу «спроси ФЛАЙ» ASR обычно приводит к нижнему регистру, поэтому в
правиле хранятся строчные варианты. Если фраза всё равно уходит Алисе,
проверьте `make routes` и `conversation_log`.

## Камера (сценарий FLAI)

Если внешняя LLM — FLAI с доступом к камере, сценарий такой:

```
«Алиса, спроси ФЛАЙ: как дела в комнате A?»
  → Quasar Bridge: default_route=llm
  → прокси вырезает «спроси ФЛАЙ»
  → FLAI /v1/chat/completions: «как дела в комнате A»
  → camera_snapshot(room=kab)
  → Qwen3VL описывает изображение
  → текст → Bridge → Yandex TTS → динамик
```

FLAI не патчится: очистка обращения выполняется только прокси.

## Ограничения FLAI

1. `response_format` игнорируется; классификатор Bridge не используется,
   потому что `default_route` = `llm`.
2. `temperature`, `max_tokens`, `chat_template_kwargs` игнорируются.
3. `tools`, `tool_choice`, `functions` игнорируются. Поэтому инструменты
   Bridge (`assistant_tools`) лучше держать выключенными.
4. Сложный запрос может идти 30–50 с. Таймаут Bridge — 60 с.
5. FLAI хранит сессии; голосовые запросы видны в веб-чате.

Для другой LLM эти ограничения могут отличаться — проверьте её поддержку
OpenAI API.

## Отдельный пользователь FLAI (по желанию)

Чтобы голосовые запросы не смешивались с личной историей:

1. В FLAI: «Администрирование» → «Пользователи» → создать `alice`.
2. Войти как `alice`, создать API-ключ.
3. Заменить `secrets/flai-token`.
4. Перезапустить Bridge.
