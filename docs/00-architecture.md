# 00. Архитектура

## Голосовой тракт после установки

```
Пользователь
   │  «Алиса, спроси нейросеть: …»
   ▼
Станция Лайт 1 (yandexmicro)
   │  микрофоны + VQE, wake word
   ▼
Облако Яндекса: STT
   │  распознанный текст
   ▼
Quasar Bridge (на колонке, 127.0.0.1:8443)
   ├─ правила routes (погода, музыка, таймеры) ──► Яндекс
   ├─ classifier (FLAI /v1/chat/completions) ───► FLAI
   └─ LLM-запрос ───────────────────────────────► FLAI
                                                       │
                                                       ▼
                                              OpenAI-совместимый API
                                              http://192.168.1.2:5000/v1
                                                       │
                                                       ▼
                                              Qwen3VL-8B / router
   ┌───────────────────────────────────────────────────┘
   ▼
Облако Яндекса: TTS
   │  аудио
   ▼
Динамик колонки
```

Важно: **STT и TTS остаются в облаке Яндекса**. Локально генерируется
только текст ответа. Это гибрид, а не полностью приватный ассистент.

### Ветка с камерой

```
«Алиса, спроси ФЛАЙ: как дела в комнате A?»
  → Bridge: правило explicit_llm_phrase → route=llm
  → FLAI: camera_snapshot(room=kab)
  → flai-room-snapshot-api: /snapshot/kab
  → Qwen3VL описывает снимок
  → текст → Bridge → Yandex TTS → динамик
```

Это штатный сценарий: FLAI отвечает за текст и анализ изображения,
Яндекс — за распознавание речи и озвучивание.

## Компоненты

| Компонент | Где | Роль |
|---|---|---|
| Станция Лайт 1 | `192.168.1.101` | микрофоны, динамик, кнопки, свет |
| Quasar / maind | на колонке | штатный голосовой тракт Алисы |
| Quasar Bridge | на колонке, `/data/opt/quasar-bridge` | слушает локальный трафик, решает, кто отвечает |
| FLAI | `192.168.1.2:5000` | локальная LLM, роутер запросов, GPU |
| lite-kit | `192.168.1.2:53/80/443` | только на этапе root: DNS + HTTPS + ADB |
| Роутер TP-Link | `192.168.1.1` | DHCP/DNS на время root |

## Этап root

```
Сброс колонки
   │
   ▼
factory-образ в recovery
   │  get_sync_info -> quasar.yandex.net
   ▼
DNS роутера -> 192.168.1.2
   │
   ▼
lite-kit: HTTPS 443, сертификат eMudhra
   │  ответ с adbd.remoteActivation=true
   │  и манифест .46
   ▼
колонка скачивает .46, ставит, перезагружается
   │
   ▼
adbd на 5555 (root)
   │
   ▼
Dropbear на 2222 + отключение OTA
```

## Порты и адреса

IP колонки может измениться после сброса или переподключения. Скрипты
ищут её по `device_id`/MAC через `scripts/resolve-speaker.sh`; в таблице
ниже — текущий снимок.

| Адрес | Порт | Что |
|---|---|---|
| `192.168.1.101` | `1961/tcp` | glagol WebSocket (облачный токен) |
| `192.168.1.101` | `7447/tcp` | Zenoh |
| `192.168.1.101` | `5555/tcp` | ADB, только на этапе root |
| `192.168.1.101` | `2222/tcp` | Dropbear SSH после настройки |
| `192.168.1.2` | `5000/tcp` | FLAI HTTP API |
| `192.168.1.2` | `53/tcp,udp` | lite-kit DNS (временно) |
| `192.168.1.2` | `80/443/tcp` | lite-kit HTTP/HTTPS (временно) |

## Границы доверия

- Домашняя сеть считается доверенной.
- FLAI и lite-kit не должны быть доступны из интернета.
- SSH на колонке изначально без пароля; ключ обязателен.
- API-ключ FLAI — секрет; он лежит в `secrets/`, не в git.
- Прошивка и сторонние бинарники — неофициальные; проверяйте суммы.
