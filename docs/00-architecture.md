# 00. Архитектура

## Голосовой тракт после установки

```
Пользователь
   │  «Алиса, …»
   ▼
Станция Лайт 1 (yandexmicro)
   │  микрофоны + VQE, wake word
   ▼
Облако Яндекса: STT
   │  распознанный текст
   ▼
Quasar Bridge (на колонке, 127.0.0.1:8443)
   ├─ yandex_services / home_devices / home_state / speaker_playback / speaker_controls / yandex_intercom ──► Яндекс
   │     погода, время, музыка, умный дом, пауза/стоп, сообщения между колонками
   │
   └─ всё остальное (default_route=llm) ────────────────► LLM-роутер :5002 /v1
                                                       │  выбор по ключу колонки
                                                       ├─ primary ──► upstream 1
                                                       ├─ fallback 1 ─► upstream 2
                                                       └─ fallback 2..9 ─► …
                                                          (любые OpenAI-совместимые LLM)
                                                       │
                                                       ▼
                                              модель провайдера
   ┌───────────────────────────────────────────────────┘
   ▼
Облако Яндекса: TTS
   │  аудио
   ▼
Динамик колонки
```

Важно: **STT и TTS остаются в облаке Яндекса**. Локально генерируется
только текст ответа. Это гибрид, а не полностью приватный ассистент.

### Ветка с камерой

```
«Алиса, как дела в комнате A?»
  → Bridge: default_route=llm
  → FLAI: camera_snapshot(room=kab)
  → flai-room-snapshot-api: /snapshot/kab
  → Qwen3VL описывает снимок
  → текст → Bridge → Yandex TTS → динамик
```

Это штатный сценарий: FLAI отвечает за текст и анализ изображения,
Яндекс — за распознавание речи и озвучивание.

## Компоненты

| Компонент | Где | Роль |
|---|---|---|
| Станция Лайт 1 | `192.168.1.101` | микрофоны, динамик, кнопки, свет |
| Quasar / maind | на колонке | штатный голосовой тракт Алисы |
| Quasar Bridge | на колонке, `/data/opt/quasar-bridge` | слушает локальный трафик, решает, кто отвечает |
| LLM-роутер | `192.168.1.2:5002` | выбирает upstream по промежуточному ключу, цепочка primary + fallback 1..9 |
| Внешняя LLM | например `192.168.1.2:5000` | любая OpenAI-совместимая модель: локальная или облачная |
| lite-kit | `192.168.1.2:53/80/443` | только на этапе root: DNS + HTTPS + ADB |
| Web UI | `127.0.0.1:8080` в Docker | колонки, прошивка, маршруты, ключи, бэкапы, аудит |
| `router-control` | внутренняя сеть `control` | узкий sidecar: только перезапуск `llm-router` |
| `stand-control` | внутренняя сеть `control` | узкий sidecar: только start/stop/status `lite-kit` |
| Локальный TTS `tts` | порт `8083` внутри compose | Piper: текст в WAV для кнопки «Сказать», наружу не публикуется |
| Роутер TP-Link | `192.168.1.1` | DHCP/DNS на время root |

```
Сброс колонки
   │
   ▼
factory-образ в recovery
   │  get_sync_info -> quasar.yandex.net
   ▼
DNS роутера -> 192.168.1.2
   │
   ▼
lite-kit: HTTPS 443, сертификат eMudhra
   │  ответ с adbd.remoteActivation=true
   │  и манифест .46
   ▼
колонка скачивает .46, ставит, перезагружается
   │
   ▼
adbd на 5555 (root)
   │
   ▼
Dropbear на 2222 + отключение OTA
```

## Порты и адреса

IP колонки может измениться после сброса или переподключения. Скрипты
ищут её по `device_id`/MAC через `scripts/resolve-speaker.sh`; в таблице
ниже — текущий снимок.

| Адрес | Порт | Что |
|---|---|---|
| `192.168.1.101` | `1961/tcp` | glagol WebSocket (облачный токен) |
| `192.168.1.101` | `7447/tcp` | Zenoh |
| `192.168.1.101` | `5555/tcp` | ADB, только на этапе root |
| `192.168.1.101` | `2222/tcp` | Dropbear SSH после настройки |
| `192.168.1.2` | `5000/tcp` | пример upstream LLM (FLAI или другая) |
| `192.168.1.2` | `5002/tcp` | LLM-роутер (OpenAI-совместимый) |
| `192.168.1.2` | `53/tcp,udp` | lite-kit DNS (временно) |
| `192.168.1.2` | `80/443/tcp` | lite-kit HTTP/HTTPS (временно) |
| `127.0.0.1` | `8080/tcp` | Web UI (по умолчанию только localhost) |
| внутренняя сеть | `8081/tcp` | `router-control`, наружу не публикуется |
| внутренняя сеть | `8082/tcp` | `stand-control`, наружу не публикуется |

## Веб-панель

Панель — Flask-приложение в Docker. Она не получает полный Docker API:
перезапуск роутера и управление стендом выполняют два узких sidecar.

```
Браузер (LAN)
   │ HTTP + пароль/сессия
   ▼
webui :8080
   ├─ local/speakers, secrets, backups, webui-state
   ├─ router-control :8081 ──► docker restart llm-router
   └─ stand-control :8082 ──► docker start/stop/status lite-kit
```

Возможности:

- статус колонок, Bridge, routing, ключи, SSH/OTA;
- вкладка «Прошивка»: скачивание образа, запуск/остановка `lite-kit`,
  поиск колонки, действия после root; сброс и привязка остаются ручными;
- маршруты: primary + до 9 fallback, порядок стрелками, проверка
  доступности через `GET /models`;
- ключи: промежуточные токены и общий список upstream-ключей;
- шифрованные бэкапы всей конфигурации или одной колонки;
- аудит действий и смена пароля.

## Границы доверия

- Домашняя сеть считается доверенной.
- LLM-сервер и lite-kit не должны быть доступны из интернета.
- SSH на колонке изначально без пароля; ключ обязателен.
- Ключи роутера и upstream-ключи — секреты; они лежат в `secrets/`,
  не в git. Колонки знают только промежуточный `sk-router-*`.
- `secrets/webui-admin.hash` и `secrets/webui-session.key` — секреты
  панели. Пароль задаётся через `make webui-passwd`.
- `router-control` и `stand-control` имеют доступ к Docker socket.
  Они доступны только панели по внутренней сети и не публикуют порты.
- `stand-control` запускает контейнер с `network_mode: host` (DNS 53,
  HTTP 80, HTTPS 443). Запускайте стенд только на время прошивки.
- Архивы бэкапов содержат ключи и SSH-ключ, поэтому всегда шифруются
  паролем. Пароль не хранится.
- Проверка доступности `GET /models` отправляет upstream-ключ выбранному
  провайдеру; это тот же ключ, который роутер использует для запросов.
- Прошивка и сторонние бинарники — неофициальные; проверяйте суммы.
