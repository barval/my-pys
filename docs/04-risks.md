# 04. Риски, ограничения и откат

## Ограничения v1.0

1. **Это не полностью приватный ассистент.** Quasar Bridge оставляет
   распознавание и синтез речи в облаке Яндекса. В облако уходит аудио
   запроса и ответа, даже когда текст ответа сгенерировала локальная модель.
2. **FLAI — не часть колонки.** Если хост `192.168.1.2` выключен или
   контейнер FLAI недоступен, сложные вопросы не работают. Погода, музыка,
   таймеры и умный дом продолжат работать через Яндекс.
3. **Латентность.** Простой ответ FLAI — около 5 с, сложный — до 30–40 с.
   Таймаут Quasar Bridge на запрос к LLM — 60 с, на классификатор — 8 с
   по умолчанию. Классификатор нужно поднять до 45 с.
4. **`response_format` не работает.** FLAI игнорирует параметр. Классификатор
   полагается на системный промпт «верни только JSON». Это проверено, но
   хрупко: смена модели/промпта может сломать автоматическую маршрутизацию.
   Явная фраза «спроси нейросеть» обходит классификатор.
5. **ARM64-бинарник на 32-битном userspace.** Ядро Лайт 1 — aarch64, но
   userspace armhf. Статический Go-бинарник ARM64 должен работать; в README
   Quasar Bridge работа на Лайт подтверждена. Если получите
   `Exec format error` — ставьте ARMv7-сборку вручную.
6. **Прошивка `.46` — сторонняя.** Скачивается с зеркала `lite-kit`.
   Проверяйте размер, CRC32 и SHA-256 из `manifest.json`. Не прерывайте
   установку: recovery-образ цел, но процесс придётся начинать заново.
7. **Сброс необратим для `/data`.** Все настройки и установленный софт
   пропадут. Колонку нужно заново привязать к аккаунту.
8. **SSH с пустым паролем.** Dropbear запускается с `-B`, иначе вход
   отклоняется. Любой в локальной сети может войти. Закройте это ключом и
   уберите `-B` сразу после проверки.
9. **FLAI API без TLS.** Ключ передаётся по локальной сети в заголовке
   `Authorization` в открытом виде. Не публикуйте порт 5000 в интернет.
10. **FLAI хранит историю.** Голосовые запросы видны в веб-чате FLAI.
    Для изоляции заведите отдельного пользователя `alice` и отдельный ключ.

## Реестр рисков

| Риск | Вероятность | Последствия | Меры |
|---|---|---|---|
| Сброс не завершился, колонка не привязывается | Низкая | Колонка не работает | Повторить сброс; DNS включать только на экране Wi-Fi; телефон выключить из Wi-Fi |
| Прошивка после 21.10.2026 не принимает стенд | Средняя | Нет ADB | Стенд с `run/downgrade` и `.46`; factory-образ доверяет сертификату |
| ADB не поднимается | Средняя | Нельзя продолжить | Проверить DNS, логи стенда, `get_sync_info`, отключить DNS-фильтры |
| Колонка «кирпич» после прошивки | Низкая | Восстановление только recovery | Не выдёргивать питание; recovery-образ factory цел; сброс кнопкой |
| ARM64-бинарник не запускается | Низкая | Bridge не работает | Установить ARMv7-сборку вручную |
| Bridge не стартует после перезагрузки | Низкая | Алиса молчит | Проверить `/etc/init.d/S96quasar-bridge`; `control.sh status`; rollback |
| Ответ FLAI дольше 60 с | Средняя | Bridge обрывает запрос | Поднять `timeout_ms` классификатора; не запускать тяжёлые задачи FLAI одновременно; выбрать быструю модель |
| FLAI вернул не JSON | Низкая | Маршрут ушёл в Яндекс | Явная фраза «спроси нейросеть»; проверить `check-backends`; при необходимости `default_route: llm` |
| Ключ FLAI утёк | Низкая | Доступ к FLAI | Отозвать ключ в веб-интерфейсе, создать новый, обновить `secrets/flai-token` |
| OTA снова включились | Низкая | Root пропал | Проверить `yandex-noupdate.sh status`; повторить; не возвращать DNS до этапа 2 |
| Роутер сбросил DNS | Низкая | Привязка/стенд не работают | Проверить `nslookup`; повторить настройку |
| Другие станции в сети получили DNS стенда | Средняя | Чужая колонка обновится/получит ADB | Выключить вторую станцию `192.168.1.100` на время root; после — включить |

## Откат Quasar Bridge

Порядок важен: сначала вернуть Алисе прямое подключение, потом удалять
программу.

```sh
sh /data/opt/quasar-bridge/app/control.sh rollback
reboot
```

Проверить, что Алиса отвечает как раньше. Затем:

```sh
sh /data/opt/quasar-bridge/app/uninstall.sh
```

Настройки, ключи и журналы остаются в `/data/opt/quasar-bridge`; удалите
каталог вручную, если не нужен.

## Откат root-правок

- OTA: `sh /data/opt/yandex-noupdate.sh restore`.
- SSH: удалить `/etc/init.d/S99zdropbear` и перезагрузить.
- ADB-маркеры: удалить `/data/quasar/activate_adb_*` (но ADB может
  понадобиться как запасной вход).
- Полный сброс: кнопка паузы при подаче питания, как в `docs/03-runbook.md`.

## Что делать, если колонка замолчала

1. Не паниковать и не выдёргивать питание во время прошивки.
2. Подключиться по SSH/ADB.
3. `sh /data/opt/quasar-bridge/app/control.sh status` и `logs`.
4. Если Bridge не запускается — `control.sh rollback`, `reboot`.
5. Если SSH/ADB недоступны — сброс кнопкой; `/data` очистится, но
   factory-recovery останется.
6. Если не помогает — recovery-образ и повторная привязка.

## Правовые и этические заметки

- Всё делается только на своём устройстве и в своей сети.
- Не публикуйте ключи, `devices.json`, MAC-адреса и серийные номера.
- Модификация системных разделов может лишить гарантии.
- Quasar Bridge, lite-kit и FLAI — неофициальные проекты, не связанные
  с Яндексом.
