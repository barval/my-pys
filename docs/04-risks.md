# 04. Риски, ограничения и откат

## Ограничения v2.2

1. **Это не полностью приватный ассистент.** Quasar Bridge оставляет
   распознавание и синтез речи в облаке Яндекса. В облако уходит аудио
   запроса и ответа, даже когда текст ответа сгенерировала локальная модель.
2. **Внешняя LLM — не часть колонки.** Если хост с репозиторием (в
   примерах `192.168.1.2`) выключен,
   LLM недоступна, все не-сервисные вопросы не работают. Погода,
   время, музыка, таймеры и умный дом продолжат работать через Яндекс.
3. **Латентность.** Простой ответ LLM — около 5 с, сложный — до 30–50 с.
   Таймаут Quasar Bridge на запрос к LLM — 60 с. Классификатор в текущей
   политике не используется: `default_route = llm`.
4. **Политика маршрутизации.** Яндекс получает погоду, время, музыку,
   таймеры, умный дом и сообщения между колонками (`yandex_intercom`);
   всё остальное уходит в LLM. Ошибка в правилах `yandex_services`,
   `home_devices` или `yandex_intercom` отправит сервисный запрос в LLM
   или наоборот. Проверяйте через `-route` и `make routes`.
5. **ARM64-бинарник на 32-битном userspace.** Ядро Лайт 1 — aarch64, но
   userspace armhf. Статический Go-бинарник ARM64 должен работать; в README
   Quasar Bridge работа на Лайт подтверждена. Если получите
   `Exec format error` — ставьте ARMv7-сборку вручную.
6. **Прошивка `.46` — официальная, но старой сборки.** Скачивается с
   официального CDN Яндекса по фиксированному URL, зеркало `lite-kit`
   используется только как источник альтернативных ссылок. Проверяйте
   размер, CRC32 и SHA-256 из `manifest.json`. Не прерывайте установку:
   recovery-образ цел, но процесс придётся начинать заново.
7. **Сброс необратим для `/data`.** Все настройки и установленный софт
   пропадут. Колонку нужно заново привязать к аккаунту.
8. **SSH с пустым паролем.** Dropbear запускается с `-B`, иначе вход
   отклоняется. Любой в локальной сети может войти. Закройте это ключом и
   уберите `-B` сразу после проверки.
9. **LLM API без TLS.** Ключ передаётся по локальной сети в
   заголовке `Authorization` в открытом виде. Не публикуйте порт 5000
   в интернет.
10. **LLM хранит историю.** Голосовые запросы видны в истории провайдера.
    Для изоляции заведите отдельного пользователя и отдельный ключ.
11. **Локальный TTS по умолчанию доступен в сети.** Для Piper `make webui`
    публикует порт `8083` на `TTS_BIND` (по умолчанию `0.0.0.0`), без
    пароля и с лимитом 1000 символов на запрос. Ограничьте `TTS_BIND`
    адресом хоста или закройте порт файрволом.

## Риски веб-панели

- Панель и sidecar’ы должны быть доступны только из доверенной локальной
  сети. Порт `8080` по умолчанию слушается на `127.0.0.1`.
- `router-control` и `stand-control` имеют доступ к Docker socket.
  Компрометация панели ограничена их фиксированными действиями (restart
  `llm-router`; start/stop/status `lite-kit`), но это всё равно
  привилегированные операции.
- `stand-control` запускает `lite-kit` с `network_mode: host`: DNS 53,
  HTTP 80, HTTPS 443 на хосте. Держите стенд выключенным вне прошивки.
- Пароль панели хранится как scrypt-хеш в `secrets/webui-admin.hash`.
  Слабый пароль или доступ к `secrets/` даёт доступ к управлению.
- Архивы бэкапов содержат ключи и SSH-ключ и не шифруются. Храните их как
  секреты.
- Восстановление бэкапа заменяет конфигурацию. Перед заменой создаётся
  снапшот текущих файлов в `webui-state/restore-backups/`.
- Проверка доступности `GET /models` может давать ложную ошибку, если
  провайдер не поддерживает этот endpoint. Это не влияет на обычные
  запросы, но статус в панели может вводить в заблуждение.
- Цепочка fallback до 9 маршрутов увеличивает максимальное время
  ожидания: каждый upstream добавляет свой таймаут.

## Реестр рисков

| Риск | Вероятность | Последствия | Меры |
|---|---|---|---|
| Сброс не завершился, колонка не привязывается | Низкая | Колонка не работает | Повторить сброс; DNS включать только на экране Wi-Fi; телефон выключить из Wi-Fi |
| Прошивка после 21.10.2026 не принимает стенд | Средняя | Нет ADB | Стенд с `run/downgrade` и `.46`; factory-образ доверяет сертификату |
| ADB не поднимается | Средняя | Нельзя продолжить | Проверить DNS, логи стенда, `get_sync_info`, отключить DNS-фильтры |
| Колонка «кирпич» после прошивки | Низкая | Восстановление только recovery | Не выдёргивать питание; recovery-образ factory цел; сброс кнопкой |
| ARM64-бинарник не запускается | Низкая | Bridge не работает | Установить ARMv7-сборку вручную |
| Bridge не стартует после перезагрузки | Низкая | Алиса молчит | Проверить `/etc/init.d/S96quasar-bridge`; `control.sh status`; rollback |
| Ответ LLM дольше 60 с | Средняя | Bridge обрывает запрос | Выбрать более быструю модель; не запускать тяжёлые задачи на GPU одновременно |
| LLM вернула ошибку/пустой ответ | Низкая | Bridge скажет, что не получилось | Проверить upstream, ключ, модель; `check-backends` |
| Ключ LLM утёк | Низкая | Доступ к LLM | Отозвать ключ у провайдера, создать новый и обновить его в «Модели и доступ → Ключи» |
| Утёк пароль панели | Низкая | Управление колонками/ключами | Сменить пароль, удалить `secrets/webui-session.key`, проверить аудит |
| Стенд оставлен включённым | Средняя | DNS/порты 53/80/443 заняты | Остановить стенд из панели или `stop-lite-kit.sh` |
| Незащищённый бэкап | Низкая | Утечка ключей | Архив не шифруется; хранить его как секрет с доступом только для администратора |
| OTA снова включились | Низкая | Root пропал | Проверить `yandex-noupdate.sh status`; повторить; не возвращать DNS до завершения прошивки и привязки |
| Роутер сбросил DNS | Низкая | Привязка/стенд не работают | Проверить `nslookup`; повторить настройку |
| Другие станции в сети получили DNS стенда | Средняя | Чужая колонка обновится/получит ADB | Выключить `192.168.1.100`, `192.168.1.102`, `192.168.1.103` на время root; после — включить. Все четыре MAC → IP закрепить в DHCP |

## Откат Quasar Bridge

Порядок важен: сначала вернуть Алисе прямое подключение, потом удалять
программу.

```sh
sh /data/opt/quasar-bridge/app/control.sh rollback
reboot
```

Проверить, что Алиса отвечает как раньше. Затем:

```sh
sh /data/opt/quasar-bridge/app/uninstall.sh
```

Настройки, ключи и журналы остаются в `/data/opt/quasar-bridge`; удалите
каталог вручную, если не нужен.

## Откат root-правок

- OTA: `sh /data/opt/yandex-noupdate.sh restore`.
- SSH: удалить `/etc/init.d/S99zdropbear` и перезагрузить.
- ADB-маркеры: удалить `/data/quasar/activate_adb_*` (но ADB может
  понадобиться как запасной вход).
- Полный сброс: кнопка паузы при подаче питания, как в `docs/03-runbook.md`.

## Что делать, если колонка замолчала

1. Не паниковать и не выдёргивать питание во время прошивки.
2. Подключиться по SSH/ADB.
3. `sh /data/opt/quasar-bridge/app/control.sh status` и `logs`.
4. Если Bridge не запускается — `control.sh rollback`, `reboot`.
5. Если SSH/ADB недоступны — сброс кнопкой; `/data` очистится, но
   factory-recovery останется.
6. Если не помогает — recovery-образ и повторная привязка.

## Правовые и этические заметки

- Всё делается только на своём устройстве и в своей сети.
- Не публикуйте ключи, `devices.json`, MAC-адреса и серийные номера.
- Модификация системных разделов может лишить гарантии.
- Quasar Bridge, lite-kit и FLAI — неофициальные проекты, не связанные
  с Яндексом.
