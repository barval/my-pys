# Web UI

Локальная панель для обслуживания колонок, LLM-роутера и ключей.
Работает в Docker: на хосте нужен только Docker, Python/Flask/ssh/adb
внутри контейнера не устанавливаются.

## Что умеет

- показывает профили колонок из `local/speakers/` с полными MAC и
  device ID, моделью и цветной иконкой;
- запускает разрешённые действия: статус Bridge, проверку LLM, запись
  ключа, routing, установку Bridge, подготовку root/SSH;
- показывает лог задания в реальном времени;
- читает и сохраняет `secrets/router-routes.json`, проверяя его через
  штатный `load_config()` роутера;
- генерирует и ротирует промежуточные токены, записывает upstream-ключи;
- ведёт журнал действий в `webui-state/audit.jsonl`.

Чего панель **не** делает:

- не выполняет сброс колонки и первичную привязку в приложении
  «Дом с Алисой» — это ручные шаги из `docs/03-runbook.md`;
- не показывает существующие значения ключей (только «есть/нет»);
- не принимает произвольные shell-команды: только белый список.

## Установка и запуск

```bash
make webui-passwd   # задать пароль (выполняется внутри контейнера)
make webui          # собрать и запустить панель
```

Панель слушает `http://127.0.0.1:8080`.

Полезные команды:

```bash
make webui-logs     # логи
make webui-stop     # остановить
make webui-passwd   # сменить пароль
```

Пароль также меняется прямо в панели: экран «Пароль» в верхнем меню.
После смены текущая сессия завершается, нужно войти заново.

Пароль хранится как scrypt-хеш в `secrets/webui-admin.hash` с режимом
`0600`. Сессионный ключ создаётся автоматически в
`secrets/webui-session.key`.

## Как устроен контейнер

В compose два сервиса:

| Сервис | Роль |
|---|---|
| `webui` | Flask-панель, SSH/ADB/curl, работа с профилями и ключами |
| `router-control` | узкий sidecar: умеет только перезапускать `llm-router` |

`router-control` — единственный контейнер с доступом к
`/var/run/docker.sock`. Он не публикует порт и находится во внутренней
сети `control`, доступной только панели. Панель не получает Docker API.

Монтирования:

- репозиторий `/app` — только чтение;
- `secrets/`, `webui-state/`, `backups/`, `.cache/` и каталог прошивок —
  чтение-запись;
- `local/` — только чтение (профили колонок).

Контейнер запускается от UID/GID хоста, с `read_only`, `cap_drop: ALL`
(добавлен только `NET_RAW` для `ping`/ARP), `no-new-privileges` и
отдельным `tmpfs` для `/tmp`.

Если Docker-сокет принадлежит другой группе, задайте её явно:

```bash
DOCKER_GID=$(stat -c '%g' /var/run/docker.sock) make webui
```

Если ваш UID/GID не 1000:

```bash
WEBUI_UID=$(id -u) WEBUI_GID=$(id -g) make webui
```

## Доступ по локальной сети

По умолчанию порт опубликован только на `127.0.0.1`. Чтобы открыть его
для локальной сети:

```bash
WEBUI_BIND=0.0.0.0 make webui
```

Не публикуйте порт в интернет и не пробрасывайте его на роутере. Если
нужен HTTPS, ставьте панель за локальный nginx и не открывайте порт
наружу.

## Разработка на хосте

Контейнер — основной способ запуска. Для отладки кода можно запустить
панель на хосте:

```bash
python3 -m pip install -r requirements-webui.txt
python3 -m webui.admin set-password
make webui-dev
```

В этом режиме `WEBUI_ROUTER_CONTROL=host`, и кнопки start/stop/restart
вызывают `docker compose` напрямую. Для systemd используйте
`deploy/webui.service`, заменив `User`, `WorkingDirectory` и путь в
`ExecStart`.

## Действия

Колонка:

| Действие | Что делает |
|---|---|
| `status` | версия Bridge, процесс, `check-backends`, место на `/data` |
| `check` | тестовый запрос к LLM через роутер |
| `key` | записывает `LLM_*` из профиля в `runtime.env` колонки |
| `routing` | применяет политику маршрутизации Bridge |
| `bridge` | ставит/обновляет Quasar Bridge |
| `root` | настраивает SSH/Dropbear и отключает OTA |

Хост:

| Действие | Что делает |
|---|---|
| `firmware` | скачивает прошивку |
| `router-restart` | перезапускает `llm-router` через sidecar |

В контейнерном режиме кнопок start/stop нет: sidecar намеренно умеет
только перезапуск. Запуск и остановка стека — `make router` /
`make router-stop` на хосте.

Задания на одну колонку выполняются строго по очереди. Логи:
`webui-state/jobs/<id>.log`.

## Ключи

- Промежуточный токен: `secrets/router-token-<route>`.
- FLAI: `secrets/flai-token-<route>`.
- Orca: `secrets/orca-token-<route>`.

Новый токен показывается один раз после ротации. Сразу после этого
запишите его в колонку:

```bash
SPEAKER_ENV=local/speakers/<name>.env ./scripts/set-speaker-key.sh
```

## Модель и цвет колонки

Модель по умолчанию для платформы `yandexmicro` — «Яндекс Станция Лайт»
(в device-tree устройство называется `Yandex Station Micro v1.2`).
Переопределить можно в профиле:

```env
SPEAKER_ROOM=Комната B
SPEAKER_MODEL=Яндекс Станция Лайт
```

`SPEAKER_ROOM` показывается под именем профиля в списке колонок.

Цвет корпуса **не определяется достоверно по MAC или device ID**: в
устройстве нет поля с цветом, `Board_id` — это ревизия платы. Цвет
задаётся вручную в карточке колонки, кнопка «Сохранить». Выбор
сохраняется в `webui-state/speaker-appearance.json`, профили не
изменяются.

Доступные цвета: бежевый, зелёный, розовый, красный, фиолетовый,
жёлтый, голубой, серый, чёрный, белый. Принимаются и маркетинговые
названия: `cappuccino` (капучино), `mint` (мята), `flamingo` (фламинго),
`ultraviolet` (ультравиолет), `chili` (чили), `lemon` (лимон). Режим
«Авто» выбирает стабильный цвет по device ID, чтобы колонки
различались, но он не обязан совпадать с реальным корпусом.

Профили перечитываются автоматически при изменении файлов в
`local/speakers/` — перезапуск панели для смены комнаты или цвета не
нужен.

## Если не видны полные MAC/Device ID

Обычно это старый контейнер. Обновите и пересоздайте его:

```bash
git pull --ff-only
make webui
```

`make webui` теперь делает `--force-recreate`, а шаблоны и CSS
перезагружаются без кеша. В браузере сделайте `Ctrl+Shift+R`.

## Резервные копии

Экран `/backup` создаёт шифрованные архивы настроек. Пароль задаётся при
создании и не сохраняется; без него архив не открыть.

Два режима:

- **Вся конфигурация** — `local/.env`, все профили колонок,
  `secrets/router-routes.json`, все `router-token-*`, `flai-token-*`,
  `orca-token-*`, `secrets/speaker_ed25519`, `.pub` и
  `secrets/webui-admin.hash`.
- **Одна колонка** — её профиль, её ключи и её маршрут из
  `secrets/router-routes.json`.

Не попадают в архив: `webui-session.key`, логи, `router-state` и аудит.

Архивы лежат в `backups/config/` с режимом `0600` и скачиваются только
администратором. Формат — `.tar.gz.enc` (AES-GCM, ключ из PBKDF2).

Восстановление:

1. Сначала создаётся снапшот текущих файлов в
   `webui-state/restore-backups/<timestamp>/`.
2. Архив расшифровывается и проверяется.
3. «Вся конфигурация» заменяет профили, ключи и конфиг роутера; «одна
   колонка» обновляет только её.
4. Обязательно введите `REPLACE` — без этого восстановление не начнётся.

Перенос на другой хост:

```bash
# на старом хосте
make webui
# открыть /backup, создать архив «Вся конфигурация», скачать его

# на новом хосте
git clone <repo> && cd my-pys
make webui-passwd
make webui
# открыть /backup, загрузить архив, ввести пароль и REPLACE
```

После восстановления роутер подхватит конфиг автоматически. Если
Docker-сокет принадлежит другой группе, задайте `DOCKER_GID` перед
запуском.

## Аудит и отзыв доступа

- `webui-state/audit.jsonl` — последние действия; старые записи можно
  удалять вручную.
- Сменить пароль: экран «Пароль» в панели или `make webui-passwd`.
- Отозвать все сессии: удалить `secrets/webui-session.key` и
  перезапустить панель.
- Полностью отключить вход: удалить `secrets/webui-admin.hash` — вход
  вернёт `503`, пока пароль не задан снова.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WEBUI_HOST` | `127.0.0.1` | адрес прослушивания |
| `WEBUI_PORT` | `8080` | порт |
| `WEBUI_ROOT` | текущий каталог | корень проекта |
| `WEBUI_JOB_TIMEOUT` | `600` | таймаут задания, секунд |
| `WEBUI_MAX_WORKERS` | `2` | одновременных заданий |

## Диагностика

- Панель не стартует: проверьте, что установлен Flask и задан пароль.
- `503` на форме входа: нет `secrets/webui-admin.hash`.
- Задание сразу `failed`: откройте его лог; чаще всего не найден профиль,
  SSH-ключ или контейнер роутера.
- Health роутера `unavailable`: контейнер `llm-router` не запущен или
  слушает другой порт.
