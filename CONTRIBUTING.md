# Как участвовать

## Ветки

- `master` — стабильная версия, только проверенные изменения.
- `v1.0` — текущая рабочая ветка.
- Новые изменения — отдельная ветка от `v1.0` или следующей версии.

Слияние в `master` — только по команде владельца проекта и после проверки
на живой колонке.

## Коммиты

Короткое сообщение в императиве, например:

- `docs: add rollback procedure`
- `scripts: harden post-root-ssh`
- `vendor: pin quasar-bridge v0.6.2`

Один коммит — одна причина. Не смешивайте документацию, скрипты и
обновление vendor без необходимости.

## Документация

- Пишите по-русски, коротко и по делу.
- Команды — в блоках `bash`/`sh`, с ожидаемым результатом.
- Пути — от корня репозитория.
- Не обещайте того, что не проверено: помечайте `не проверено` или
  `ожидает`.
- Секреты, MAC-адреса и серийные номера не публикуйте.

## Безопасность

- `secrets/` не коммитится.
- Не добавляйте в git `vendor/lite-kit/firmware/**/*.zip` и `backups/`.
- Перед коммитом проверьте `git status` и `git diff`.
- Если ключ попал в историю — отзовите его и перепишите историю.

## Проверки перед коммитом

```bash
bash -n scripts/*.sh
shellcheck scripts/*.sh          # если установлен
./scripts/check-flai.sh          # FLAI доступен
docker compose -f docker/docker-compose.lite-kit.yml config >/dev/null
```

Для документации достаточно `git diff` и проверки ссылок вручную.

## Обновление vendor

См. `vendor/README.md`. Фиксируйте коммит и причину обновления.
